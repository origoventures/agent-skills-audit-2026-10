# Second adversarial review, 13 October 2026

After the article was cut from about 3,400 to about 2,150 words, six independent reviewers attacked the shortened English text and this repository, each from one angle:

1. reproducibility engineer;
2. software supply-chain security researcher;
3. empirical-methods reviewer;
4. Claude Code platform expert;
5. senior editor of a Medium AI publication;
6. maintainers of the named projects.

All six were AI agents. Each cloned this repository fresh, cloned the audited projects itself at the listed commits, and executed nothing from them. The author re-checked against the source every point that changed a number or a claim.

## What was confirmed

- `audit.py` reproduced `audit.csv` (except live tag counts) and `evidence.json` byte for byte; all 20 full SHAs are consistent across files.
- Every count in the derivation table rebuilds from `classification.csv` and `recheck-2026-10-10.csv`.
- Both quotes from the Claude Code documentation are verbatim; mods are on by default from v2.1.287.
- Liu et al. (31,132 skills, odds ratio 2.12) and Snyk ToxicSkills (3,984 skills, 13.4%, 76 malicious payloads) are reported accurately.

## What changed as a result

- **Finding 1.** The heading no longer generalises to all skills. Liu et al. (Table 6) report 88.5% of marketplace skills as instruction-only; in this sample 17 of 20 go beyond instructions. The article now states the contrast and no longer says the two results point "in the same direction".
- **Hooks: 8, not 9.** graphify registers hooks only through an optional second command (`graphify claude install`). By the main-install-path rule it no longer counts; `classification.csv` and the README were updated and the article mentions it separately.
- **Churn.** The shortened article said that for 7 repositories the same install command would have brought different code. That figure had no derivation here, and two of the seven changes did not affect Claude Code. The article now gives only 11 of 20 with new commits, 9 of them in code, scripts or manifests.
- **Why the first pass missed the claude-seo mod.** `audit.py` did read `plugins/seo-cockpit/hooks/hooks.json`, but that file contains only a `modules` key, which the script did not recognise. The article's earlier explanation was wrong and has been corrected.
- **Sample concentration.** 11 of 19 third-party projects come from one article, not 10. `SAMPLE.md` is corrected.
- **Context restored after the cut:** caveman's telemetry (on by default, stored with IP, opt-out) and how to reverse its install; "credentials as their core function"; the Codex subagent still passes Claude Code's permission check before it starts; graphify sends documents, PDFs and images (not code) to Gemini only when a Gemini key is set, although its README says the skill uses the IDE session's model; Understand-Anything's switch is a config folder its README tells teams to commit; the user chooses when to update a third-party marketplace, not what arrives.
- **New case, verified at the audited commit.** In impeccable's live mode, with the default `IMPECCABLE_LIVE_COPY_AGENT=auto` and no agent session polling, applying manual text edits spawns the logged-in Codex CLI with `--dangerously-bypass-approvals-and-sandbox`, or the Claude CLI with `--permission-mode bypassPermissions` (`crates/live/src/copy_edit_agent.rs`, `run_codex` and `run_claude`; `choose_copy_edit_agent`). This is documented only in `docs/CLI-CONTRACT.md`.
- **Admin checklist.** Corrected: `#ref` takes a branch or tag, not a commit; `plugin details` does not show mods; what `allowManagedHooksOnly` and `strictPluginOnlyCustomization` do and do not cover; added `blockedMarketplaces`, `syncClaudeAiPlugins` and `disableCommandPluginSources`.
- **Limits.** The article now says that agents classified 19 of the 20 repositories, and that for three projects the main install path delivered an older version than the one audited (the two official-marketplace pins, and impeccable on npm, whose latest release on 8 October was 4.1.0).
